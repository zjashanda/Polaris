# AP+WiFi 新项目设备调试笔记

## 硬件拓扑

- AP 日志串口：`COM14@921600`
- 上位/WiFi 日志串口：`COM13@921600`
- 控制/上下电串口：`COM15@115200`
- 当前没有独立 CP 串口。

## 串口使用强约束

- `uut-switch1.on` / `uut-switch1.off` 只在控制/上下电串口 `COM15@115200` 输入。
- `uut-pa.on` / `pa-enable.set 0 17 0 1` 也只在控制/上下电串口 `COM15@115200` 输入。
- `COM14@921600` 和 `COM13@921600` 只作为 AP / 上位日志观察口，不下发 PA 命令。

## 声卡播放不生效时的 PA 前置

如果使用声卡播放唤醒词/命令词但设备侧没有反应，需要先在控制/上下电串口 `COM15@115200` 输入以下命令，注意不是 AP/上位日志串口：

```text
uut-pa.on
pa-enable.set 0 17 0 1
```

含义：

- `uut-pa.on`：打开 PA。
- `pa-enable.set 0 17 0 1`：保存/固化 PA 相关配置。

## 可在当前 AP+WiFi 设备上优先验证的能力

当前设备未连接到本机可控 Wi-Fi，所以先排除“电脑热点断开/恢复、配网、断网恢复”类网络编排。只要设备本身在线，在线识别类能力仍可验证，但不能把“断网/恢复”作为前置动作。

### 可直接或低成本适配验证

- 首次唤醒：播放 `小美小美`，断言 AP `wakeup_callback` / `Pre Wakeup` 和上位 `online_wakeup`。
- 识别模式下唤醒：先唤醒进入识别窗口，再在窗口内二次播放 `小美小美`，断言 AP/上位二次唤醒或 session 刷新。
- 唤醒响应时间 smoke：统计主机播放起点到 AP/上位首个唤醒 marker 的 proxy 延迟；无音频回采时只做趋势，不做正式门限。
- 连续唤醒、随机间隔唤醒、首次/识别模式唤醒率压测：使用 AP/上位唤醒 marker 计数，设备重启/串口中断单独归因。
- 静默误唤醒、人声干扰误唤醒、白噪声误唤醒：监听 AP/上位唤醒 marker，观察设备是否误唤醒或重启。
- 基础命令词、需求命令词和自由说 smoke：可通过先唤醒再播命令/语料验证，但断言要从旧 CP 关键词改为 AP/上位 `online_asr_callbak`、TTS、状态闭环或 intent 证据。
- one-shot 间隔矩阵：可验证唤醒词后不同间隔接命令/在线语料的识别闭环，断言同样改为 AP/上位证据。
- 自播中唤醒打断、识别打断：可先测本机可触发的长播报前置，再注入唤醒词或命令词；如果用天气/播歌，要求设备当前在线。

### 需要额外资料或环境后再验证

- 半双工/全双工模式切换：需要确认新设备的配置入口，是云端/App 接口、语音开关词，还是本地串口命令。
- 在线 VAD 专项：需要设备当前能访问云端 ASR；不要求当前电脑控制 Wi-Fi，但需要在线链路稳定。
- 音量、夜间模式、多唤醒、唤醒阈值、唤醒词变更等配置类：需要可用 App/cloud API、IoT ID/token，或设备本地等价命令。
- 上电/掉电保持：控制口已具备 `uut-switch1.on/off`，但每个配置项是否保持需要先能设置该配置项。

### 当前不作为本设备自动验证目标

- 联网/断网恢复、Windows 热点切换、清配网、重新配网：当前设备不连本机 Wi-Fi，无法由本机稳定控制网络状态。
- 依赖独立 CP 串口证据的旧断言：当前无 CP，需要改为 AP+上位证据口径。
- OTA、8 通道 AEC/录音、遥控器/面板按键、人工听辨发音人：需要额外外设、录音链路或人工判定资料。
