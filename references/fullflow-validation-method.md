# Polaris 全链路验证方法

## 适用范围

本方法用于 Polaris / 美的空调语音设备的真机验证，覆盖唤醒、会话、超时、全双工、半双工、联网、云控设置、在线/离线 ASR、空调控制命令、文档用例执行和 FAIL 收敛。

## 每轮启动规则

1. 读取 `plan.md`；不存在则创建。
2. 明确本轮目标、设备、session、串口、播放设备、网络环境和云端环境。
3. 将本轮计划写回 `plan.md`。
4. 按 `references/modular-validation-workflow.md` 拆功能点和匹配验证池。
5. 执行前先过最小门禁，门禁失败的用例判 BLOCKED。
6. 执行后将证据路径、状态和归因同步回 `plan.md` 或项目报告。

## 需求理解流程

- 设备基础：机型、环境、固件、串口拓扑、唤醒词。
- 输入方式：语音播放、云控接口、串口命令、热点/网络动作。
- 模式：在线、离线、全双工、半双工、oneshot、唤醒后命令。
- 输出：设备状态、日志标记、云端返回、TTS/tone、回读值。
- 数值：超时时长、音量值、等待窗口、重试次数。
- 持久化：重启后是否保持设置。
- 负例：不应响应、不应误执行、不支持项必须正确归因。

## 验证方案设计

| 需求类型 | 验证方式 | 主要证据 |
| --- | --- | --- |
| 唤醒/会话 | 播放唤醒词、等待命令或超时 | CP/AP/ASR wake、ASR、MODE、TTS 日志 |
| 全双工 | 播报期间继续播放命令或打断 | 播放窗口内 ASR/命令闭环 |
| 半双工 | 播报中输入 + 播报后输入 | 播报中不响应，播报后恢复响应 |
| 联网 | 热点/设备状态/云端 probe | IP、cloud status、deviceinfo、在线 ASR |
| 云控设置 | 调用 cloud control，再读日志/状态 | HTTP 返回、设备配置日志、回读值、行为 |
| 音量 | 固定值、上下调、边界、回读 | 云控返回、日志 volume、TTS 播放状态 |
| 空调语义 | 在线/离线短语探测 | ASR/keyword、NLU/TTS、控制闭环 |
| 负向/异常 | 构造不支持、断网、未唤醒、错误状态 | 禁止标记未出现且采集有效 |

## 用例设计规则

每条用例至少包含：`case_id`、功能模块、需求来源、前置条件、输入动作、观察窗口、主断言、辅断言、BLOCKED 条件、失败归因规则和证据目录。

## 执行分层

1. 环境门禁：日志、播放、网络、云控、设备身份。
2. 最小 smoke：唤醒、打开空调/查询状态、云控 probe。
3. 单能力验证：音量、夜间模式、Mic、全/半双工等。
4. 在线/离线对照：同一语义在两套链路下分别断言。
5. 状态切换：开关、重启、断网重连。
6. 文档用例全集：按自动化能力执行和聚合。
7. FAIL 收敛：控制变量、复测、最终归因。

## 最终结论规则

- `PASS`：输入、识别、业务执行、反馈和证据均闭环。
- `FAIL`：前置满足且证据充分，但行为违反当前需求。
- `BLOCKED`：环境、设备状态、云端、日志采集或前置条件不满足。
- `TODO`：需求存在但未自动化或需人工澄清。
- `INVALID`：用例/断言/脚本本身错误，应修正后重跑。
