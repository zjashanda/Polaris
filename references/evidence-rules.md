# Polaris 证据与归因规则

## 证据源职责

- `COM12 / CP`：离线识别、唤醒底层、命令/tone/部分算法侧日志。
- `COM13 / ASR`：联网、云端状态、网络侧行为、部分在线链路日志。
- `COM14 / AP`：设备主控、deviceinfo、TTS、配置、云控回调、业务执行日志。
- `COM15`：电源/复位控制，只证明执行了断电/重启动作，不直接证明业务功能。
- 云控 HTTP 返回：证明云端接口处理，不等于设备已生效。
- 播放脚本日志：证明主机输出了音频，不等于 DUT 一定听到。
- 热点状态：证明网络承载环境，不等于云端业务可用。

## 形式化判定优先级

1. 功能行为优先：设备是否完成需求动作。
2. 状态回读次之：设备配置/状态是否变化。
3. 日志互证：CP/AP/ASR 是否出现对应标记。
4. 云端返回作入口证据：HTTP 成功只是前置。
5. 人耳观察只能作辅助，不作为自动化 PASS/FAIL 主证据。

## PASS 条件

前置条件满足、输入动作真实发生、设备收到或识别到输入、业务意图匹配正确、状态变化或控制动作符合需求、反馈符合需求，并且未出现禁止行为、异常重启或状态污染。

## FAIL 条件

只有采集有效、环境和前置条件满足、用例断言无误、需求明确支持，且实测行为与需求矛盾时，才保留最终 FAIL。

## BLOCKED 条件

串口日志不可用、播放设备不可用、设备离线但用例需要在线、云 token/接口不可用、COM15 不可用且用例需要掉电/重启、设备身份缺失等，均归 BLOCKED。

## 需求问题

文档未定义预期行为、当前机型能力矩阵不支持、云端明确返回“不支持该功能”、多份文档互相矛盾或需要人工确认时，不判固件 FAIL。

## 固件问题倾向

输入到达、识别正确、需求明确支持，但设备状态机不转移；或云控下发成功且设备收到配置，但配置未应用；或重启后持久化结果与需求不符且已看到保存闭环。

## raw FAIL 收敛要求

raw FAIL 必须先检查前置门禁、输入动作、日志窗口、状态污染、在线/离线路径、云端返回、ASR/keyword/TTS 候选、控制变量复测。收敛后再输出最终 FAIL / BLOCKED / TODO / INVALID。
